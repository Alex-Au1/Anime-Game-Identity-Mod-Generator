Setup/Testing/Documentation/Architecture. Read this one first if you're new to the repo; it's the map
the other [AI Agent Help](../README.md) files assume you have. See [Setup](../Setup/CLAUDE.md) to get

## What this project is

AGIDMGen generates **identity mods**: a character's own model, unchanged, written out as a mod. In
[Anime Game Remap (AGRemap)](https://github.com/nhok0169/Anime-Game-Remap) they are step 4 of the
maintainer's thirteen-step `char <-> skin` remap pipeline ("identity mods of both"), the baseline every
later step is checked against. AGRemap built them with prototype scripts under its `Tools/`; this repo
turns that into a library of its own. [Identity Mods](../IdentityMods/CLAUDE.md) has the detail.

## Python first (2026-10-05)

The library is pure Python. A C++ / Cython layer is added **only** when some part is measured too
slow, or is plainly better done in C++ — the maintainer decides, from a measurement. Until then, a
dependency on a compiled package is a cost too: AGRemap's own GIMI generator reads dump text through
the compiled `FixRaidenBoss2.VbFile` / `IbFile`, which needs its `.pyd` and its DLLs (libz3, libcurl,
utf8proc). See [Architecture](../Architecture/CLAUDE.md).

## Operating norms

- **Commit and push only when asked, and then straight to `main` (the maintainer's practice, 2026-10-06).**
  The maintainer asks "commit and push to main" after reviewing a step. Split unrelated work into separate
  commits, and report each hash. Branch (kebab-case, e.g. `add-wwmi-generator`) and open a PR only when asked
  for one.
- **Push with `git -c http.sslBackend=schannel push`.** The default TLS backend fails here.
- **`main` is branch-protected (2026-10-06):** two CI checks are required (see [Testing](../Testing/CLAUDE.md)'s
  "CI"). The maintainer's account bypasses the rule, so a direct push succeeds and prints
  `2 of 2 required status checks are expected`. That message is expected, not an error.
- **Commit subjects are `Scope: lowercase imperative -- detail`**, AGRemap's style, e.g.
  `GIMI: write the face diffuse on ps-t1 for 6.x skins -- 6.x moved it off ps-t0`. Bodies end with
  the `Co-Authored-By:` line.
- **Several agents may share this checkout.** Never revert (`git checkout --`, `git restore`) a file
  you did not create.
- **This machine's agent sandbox cannot verify PyPI's TLS certificate (2026-10-05)**: `pip install`
  from PyPI and Sphinx's intersphinx fetches both fail with `CERTIFICATE_VERIFY_FAILED`. Do not
  disable verification to get around it; work offline (see [Setup](../Setup/CLAUDE.md)) or ask the
  maintainer.
- **Mark what you generate.** A file or folder a script wrote says so (a header line or a README), so
  the next agent does not hand-edit it.

## THE SCRIPT BUILD: ONE FILE THAT REACHES THE LIBRARY (2026-10-10)

The maintainer asked for a script build like AGRemap's, "since not everybody knows how to properly use Python".
`Tools/ScriptBuilder/main.py` compiles the script's own source, `Tools/Script` (ported from AGRemap's), into
`AGIDMGen/script build/src/AGIDMGen/AGIDMGen.py` (plus an `__init__.py` and `__main__.py`, so the folder also imports as a
package), beside `AGIDMGen/api`, as AGRemap's `script build/src/FixRaidenBoss2/AGRemap.py` sits beside its `api`. The
READMEs of `Tools/Script` and `Tools/ScriptBuilder` have the detail.

- **DEV AND PROD, AS IN AGREMAP (the maintainer's request, once `AGIDMGen` was on PyPI, 2026-10-10).** The script does
  not contain the library; it reaches it and calls the library's `AGIDMGen.main.main(argv)`. `--env prod` (the
  committed build) pip-installs `AGIDMGen` from PyPI and updates it on every run (`--disableUpdate/-dup` skips that,
  `--preRelease/-pre` takes prereleases); `--env dev` (the builder's default) reaches `AGIDMGen/api/src/py` by a path,
  with numpy and FixRaidenBoss2 already importable. The first version of the script (earlier on 2026-10-10) compiled
  the whole library in; that ended with this change.
- **So a library change reaches script users only through a PyPI release.** A change to `Tools/Script` needs a rebuild
  with `--env prod`.
- **The script's options are pre-parsed and taken off the command line**, because the library's `main` has no hook
  to register them (AGRemap's `remapMain(commandSetup = ...)` has one). `--help` prints the library's help, then the
  script's options. This works with the 0.1.0 already on PyPI; a hook would need a library release first.
- **The script is named after the library, so it must not import itself.** `AGIDMGen.py` is the script's file and
  `script build/src/AGIDMGen` a package of the same name, so `import AGIDMGen` from the script would find the script.
  `BaseApiRef.importApi` drops the script's folders from `sys.path` (and a script-build `AGIDMGen` from `sys.modules`,
  under `python -m`) for the import. Proven: run as a package, it imported site-packages' `AGIDMGen`.
- **pip runs as `python -m pip` in a subprocess**, not AGRemap's `pip._internal`. If the update fails and `AGIDMGen` is
  installed, the installed version runs (offline use); if it is not installed, the script prints the command and exits 1.
- **The script runs from its own folder** (AGRemap's `os.chdir`), so it works when double-clicked.
- **A double-click ASKS (the maintainer's request, 2026-10-10).** AGRemap's script needs no input (it fixes the folder
  it is in), but an identity mod needs a game and characters. So `main()` with NO arguments runs `askArgs()`: which
  game, which characters (or `all`), always `--download`, into the current folder. It then ends with AGRemap's
  `logger.waitExit()` ("== Press ENTER to exit ==") so the window stays open. Both go through the logger's
  `input()`, never the builtin, so a server's logger can answer. A run WITH arguments never asks or waits
  (AGRemap's CLI always waits; ours does not, so CMD runs, CI and the testers never block). No stdin (EOF) exits 1.
  This is the README's and tutorial's Quickstart (Choice A).
- **It runs on AGRemapUtils' `ScriptBuilder`**, subclassed in `Tools/ScriptBuilder/ScriptBuilder/IDModGenScriptBuilder.py`.
  The subclass never writes to `Tools/Script`: the base class rewrites a module whose `##### Credits` are not
  AGRemap's, which would stamp AGRemap's credits over AGIDMGen's.
- **Two modules of `Tools/Script` may not define the same top-level name.** In one file the later one would overwrite
  the earlier, so the builder refuses.
- **The `.py` files under `AGIDMGen/script build/` are GENERATED.** Rebuild with `--env prod` after any change to
  `Tools/Script`; CI's `--env prod --check` fails otherwise, and on a committed `dev` build.

### THIS MACHINE'S TOOLING QUIRKS (2026-10-10)

- **Keep `Mods/` and `Data/` out of a search.** They hold several GB, and a repo-wide `grep -r` runs past
  the tool timeout. Search `AGIDMGen/`, `Testing/`, `Tools/` and `AI Agent Help/`, or pass a glob that
  excludes them.
- **After a large rewrite of `Mods/`, git is slow and `.git/index.lock` can be held.** The Claude desktop app
  runs its own `git status` / `git diff` in the background, and rehashing thousands of LFS files takes
  minutes. If a command fails on `index.lock`, check for running `git.exe` processes before anything else.
  Remove the lock only once none is left.
- **`gh` is not logged in, and the browser pane is signed out of GitHub.** Neither can change repo settings
  (branch protection, secrets), and an agent must not sign in for the maintainer. Give the maintainer the
  exact steps instead. Read-only GitHub data comes from the public API through Python:
  `urllib.request.urlopen("https://api.github.com/repos/Alex-Au1/Anime-Game-Identity-Mod-Generator/commits/<sha>/check-runs")`
  lists a commit's check names and results. `curl` fails TLS here; do not turn verification off.
- **Write a multi-line edit as a Python script in your scratch folder, or use the Edit tool.** Inline Bash
  heredocs that hold Python strings have put literal newlines into the edited files more than once, and a heredoc
  holding many quotes has failed to parse at all.
- **`git fetch` needs the schannel backend too**, not only `push`: `git -c http.sslBackend=schannel fetch origin`.
- **A commit or a branch switch can take minutes** while git rehashes `Mods/`'s LFS files. Run it in the background and
  wait for it; do not start a second git command into the lock.
- **PyPI is reachable from Python, not from pip (2026-10-10).** `urllib.request.urlopen("https://pypi.org/pypi/<name>/json")`
  works here, so read a package's published versions, upload times, `requires_dist` and wheel URLs that way (eg. to
  check that a PyPI release of AGRemapUtils has what a tool needs before CI relies on it). `pip install` from PyPI fails
  TLS. To test something against a PyPI release, fetch its wheel with `urllib` into your scratch folder and install it
  with `pip install --no-deps --no-index` into a scratch venv; never into the machine's own Python.
- **AGRemap's checkout is shared, and its compiled API can vanish mid-session (2026-10-10).** Another agent rebuilding
  AGRemap left `FixRaidenBoss2/core.cp39-win_amd64.pyd` missing for a while, and every import of `AGIDMGen` here failed
  with `No module named 'FixRaidenBoss2.core'`. That is not this repo's bug: check that the `.pyd` exists, report it, and
  rerun later. Never rebuild or switch AGRemap's checkout yourself.

### Habits


AGRemap's list of habits (its Overview, "Working a feature or bug request here") applies here in
full. The ones that matter most for a generator library:

1. **Assume failure is silent.** A generator that "ran" may have written the wrong bytes. Check the
   artifact — the files it wrote — not the exit code.
2. **Prove a refactor by byte-identical output.** Generate the same character's identity mod before and
   after, and compare every file byte for byte. A single-component character's output must stay
   byte-identical to the old naming (AGRemap's `identityMod.py` keeps exactly this check).
3. **Never validate in a circle.** A test whose expected value comes from the code under test (or from
   the text that code parsed) proves nothing. Compare against the game's own buffers.
4. **Run a new check against a broken build first.** A check that has never failed is not known to work.
   (The unit tester was checked this way on 2026-10-05: one wrong expectation made it fail.)
5. **Find the existing code before writing new.** The thing you are about to write may already exist
   in AGRemap's prototypes, tools or library — port it, and say where it came from in the commit.
6. **A one-off diagnostic becomes a tool.** If you wrote a script to check something, it goes in the
   repo for the next agent.
7. **Docstrings are published.** Write them for a new user, in the present tense: no dates, no history,
   no links into `AI Agent Help/`. History goes here.
8. **The checkout moves between your turns (2026-10-10).** The maintainer and other agents commit, switch branches
   and edit the same files while you work: in one session the checkout went from `main` to another branch, and
   commits landed that changed the feature being worked on. So, at the start of a task and again before committing,
   run `git status -sb`, `git log --oneline -5` and compare `HEAD` with `origin/main`; and re-read a file before
   editing it rather than trusting an earlier read.
9. **Commit to `main` without switching branches when you cannot.** If the checkout is on another branch whose
   `HEAD` equals `origin/main` (check `git log origin/main..HEAD` and `HEAD..origin/main` are both empty), commit there
   and `git -c http.sslBackend=schannel push origin HEAD:main`, a fast-forward. Do not switch a dirty tree onto a
   stale local `main`, and leave the branch the checkout is on alone.
10. **Ask what reaches the user, then prove that.** A change can be right in the source and still not reach anyone:
    the script build reaches the library from PyPI, so a library change reaches script users only through a release.
    Before calling a feature done, name the artifact a user runs (the PyPI package, the script, `Mods/`) and test that
    artifact, as `Testing/`'s "PROVING THE SCRIPT BUILD" does.
11. **Port AGRemap's design, then list what you changed and why.** When the maintainer says "like AGRemap", read
    AGRemap's real code first (`Tools/Script`, `Tools/ScriptBuilder`, `AGRemapUtils`), port its structure and names,
    and write each deliberate difference into the tool's README under "How it differs from AG Remap's". AGRemapUtils
    is reused through a shim (`ScriptBuilder/AGRemapUtils.py`, the tester's `src/AGRemapUtils.py`) that falls back to
    `AGREMAP_UTILS_SRC`; subclass its classes rather than copy them.
